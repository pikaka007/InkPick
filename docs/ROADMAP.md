## 已修（第十四轮）

## 已修（第十五轮）

**章节功能（V1）**。用户反馈「上游阅读软件都有章节」，本轮做了：

- `src/core/chapters.ts`：从纯文本里认出章节。实测（仿真中文 TXT）：
  **400 章 / 6.7MB 扫一遍 16ms**，1000 章 / 22.4MB 只要 48ms，**误判 0**
- 侧栏第一个区改成「文档 / 目录」两个标签：选书和选章是同一类事（导航），
  这样侧栏仍然只有两个滚动区，不会变成三段抢空间
- 头部显示当前章名 + `3 / 340`，两侧是上一章 / 下一章按钮
- 章尾一条「本章完」分隔线
- 快捷键 `[` `]` 翻章（在输入框里不抢键）
- 整本没有章节标记时（如大多数英文小说）**整个功能消失**，不给一堆垃圾章节

设计上的取舍：

- 章节**不进存档**。它是从正文纯函数推导出来的（才 16ms），因此不用改存储格式，
  而且识别规则以后改进了，旧书自动受益；存进去的话规则一改旧数据就永远过期
- 现在是「全书连续滚动 + 章节跳转」（方案 A）。**一次只显示一章**（方案 B）
  留待试用一段时间后再决定 —— B 要改搜索/跳转/恢复三处，而且会带来
  「每章都要点一下」的摩擦
- 「上一章」按阅读软件的习惯：**先回本章开头，已在开头才去上一章**

本轮还修了一个**长期存在的假失败**：侧栏拖宽的两条用 `expect(await …)` 裸读，
而 pointermove 是「连续事件」，React 会批处理，`page.evaluate` 可能在渲染前执行，
于是读到拖拽前的宽度 —— 实测约一半概率假失败。已改成 `expect.poll`。

## 已修（第十六轮）

**手动记词** —— 用户提的场景：刷视频 / 读论文时遇到生词，想顺手记下。
这不是「阅读器的附属功能」，而是把应用从「读书时才开」变成「每天都开」：
捕获（碎片时间）→ 复习（每天几分钟）→ 回到原文，是一个闭环。

本轮做的是**最简版**（窗口内加词 + 无书也能用），全局快捷键与复习调度留给后面。

- 数据模型：`Annotation` 的 `docId` 与 `anchor` 改成可选，
  **缺这两个就是「手动记的词」**
- 侧栏标注区右上角加「＋ 单词」；回车存下后**清空并保持焦点**，
  可以连着记一串而不用碰鼠标；欢迎页也有入口（侧栏收着时会先展开）
- 释义自动查（同一套 `lookupWord`），查不到就手写（复用已有的 `manualDefinition`）
- 同一个词重复记会被拦住（按 lemma **和**当时输入的原词都比一遍）
- 词表里标出「手动」来源

顺手修的两处结构性问题：

- **「全部文档」→「全部」**，且**不再在没有文档时被禁用**。
  在此之前，一个只想记单词、不导入书的用户，两个范围按钮都是灰的
  —— 根本看不到自己的词表
- **类型筛选的「全部」→「不限」**。范围那一行已经有「全部」了，
  同一个面板里两个「全部」分不清谁是谁

设计取舍：

- **不额外存 `source` 字段**，直接由「缺不缺 docId/anchor」派生。
  存两份事实早晚会出现「source 说是手动、却有 anchor」的脏数据；派生比存储可靠
- **校验写成「两者必须同进同退」**：都有 = 来自阅读，都没有 = 手动，
  只有一半 = 脏数据丢掉。而不是把半残数据带进内存里让它到处判空
- 手动词**不用逼用户填句子**：以后在书里划到同一个词会自动归到同一组，
  语境就补上了（按 lemma 分组是本来就有的行为，一行新代码都没写）

已知代价（已记入下方「一」档）：

- 去重只能拿**输入的原词**去比。`Habits`（词典还原成 `habit`）在一词已存在时
  仍然会被存下，然后在列表里合并成 ×2
- 旧版本打开新存档时，手动词会被旧的严格校验丢掉（“降级会丢字段”那个缺口的下一个具体例子）

## 已修（第十七轮）

用户实际使用后报的两个 bug：

**1. 手动词那一条点了没反应** —— 因为它在设计上确实无处可跳（没有原文位置），
但渲染成了 `<button>`，于是看起来能点。**一个点了没反应的按钮比一个不能点的行更让人困惑**。
现在它渲染成 `<div>`（`cursor: default`、悬停不变色），
「手动」标记保留，用户仍然能看出这个词是自己记的。
同一个词既有手动的、又有书里划到的时，两条按各自的来源分别渲染。

**2. 自己写的释义存下了却不显示** —— 这是个**既有 bug，不是第十六轮引入的**，
只是被手动词这个功能暴露了：按钮在有词典释义时写的就是「改写释义」（= 盖掉词典的），
但 `groupDefinition` 无条件优先词典，于是手写释义存下了却永远看不到。
现在**用户手写的优先**（想看回词典的，把输入框清空再存一次）。

顺带发现并记下的一件小事：只记手动词、不导入书的用户，一旦导入一本书，
列表会按偏好切回「本文件」，手动词就看不见了（再点一下「全部」即可）。
这是 `scope` 作为「用户偏好」的正常行为，不为它改默认值。

## 已修（第十八轮）

**三件「让应用不出事」的修补**，各自都能独立验证。

### 1. GBK 编码（档一第一条）

新增 `core/decode.ts`（纯函数，可单测）：字节 → 文本 + 用的哪种编码。
判断顺序：**UTF-8 BOM → UTF-16 BOM → UTF-8 严格试解 → 失败就用 GB18030**。

第三条是关键：**合法的 UTF-8 中文不可能由 GBK 中文字节偶然构成**，
所以「严格试解」是可靠的分界线，不用去统计标点比例。

为什么它排在最前面：**它是章节功能的前提**。GBK 文件按 UTF-8 硬读会得到「���ġ�」，
于是章节识别认 0 章、词典查不到词 —— 用户会以为那些功能没做对。
BOM 必须丢掉：留在正文里会让全文偏移整体差一格，所有标注跟着错位。

### 2. 自动备份

- 每次覆盖写之前，把上一版留成 `inkpick-store.json.bak`
- 启动时主文件解析不了就用备份顶上，并**明确告诉用户**
  （静默恢复很危险：用户只会发现「最近改的几条没了」却不知道为什么）
- 两个都坏了也不崩，退回空库

**备份前要确认待备份的内容是合法的**：主文件被外部程序改坏（比如被截断）时，
如果照样拷成 .bak，就会把唯一一份好备份覆盖掉 —— 恰恰在最需要它的时候把它毁掉。
实现上用「这份文件是不是我们自己写下的 / 启动时读过的」这个标志来判断，
而不是每次备份前重新 `JSON.parse` 一遍（大书 10MB，一分钟可能保存好几次）。

### 3. 划词收藏去重

同一个词、同一个位置重复收藏不再生成两条（手动词上一轮已经去了）。
只拦词条 —— 同一句话写两条不同的笔记是合理需求。

## 已修（第十九轮）

用户报的问题：点单词/笔记跳到原文之后，**回不到刚才读的地方**。

查下去发现比「不顺手」严重得多 —— **位置是真的丢了**：
跳转会触发滚动，而滚动会把偏移量当成「阅读进度」写进存档，
于是点一个第 2 章的词，进度就从 60% 变成 10%，关掉重开也是从那里开始。
所以修了两件事，缺一件都不算修好：

1. **跳转不再改写阅读进度。**
   区分「用户在滚」和「被跳转带着滚」：只有滚轮 / 键盘 / 摸屏 / 拖进度条
   才写阅读进度，程序性跳动不写。跳到某处之后继续往下读，下次滚动就又归用户驱动了。
2. **导航历史 + 「返回」按钮。**
   用栈而不是单个位置 —— 连着点几个词之后应该能一路退回去，和浏览器后退同一个模型。
   上限 20 步，连续压入同一位置会被忽略（否则退一次看起来像没反应）。
   标注跳转和目录跳章都会压栈。

实现上踩到一个自己没预料到的点：
**「阅读进度」和「当前视口位置」不能是同一个值。**
因为跳转不改写进度，所以连点两个词时，第二步要记的应该是
「用户当前看到哪儿」（随跳转实时更新），而不是阅读进度（还停在最开始）。
于是拆成两个概念：`onPosition` 总是上报当前视口位置，
只有 `userDriven` 为真时才写进阅读进度。

顺带修的另一个真 bug：**导入新书后 `lastDocId` 没更新** ——
导入一本书、关掉重开，打开的是**上一本**，用户会以为刚导入的书不见了。
（`loadSample` 设了，`openDocument` 漏了。写测试时碰上的。）

## 已修（第二十轮）

**复习调度（V1）** —— 上一轮说的「捕获 → 复习 → 回到原文」闭环，补上中间那一环。
在此之前，词表只能**一直变多**，没有任何手段让它们进入记忆。

- `core/review.ts`：SM-2 简化版，纯函数可单测。
  三档：忘了（间隔归零、5 分钟后再来、ease -0.2）/ 模糊（间隔 ×1.2、ease -0.05）/
  记得（1 天 → 3 天 → 按 ease 乘，ease +0.1）。ease 夹在 [1.3, 3.0]，间隔上限 365 天
- `Store.review`：**按词的 key（lemma）存，不按标注**。
  同一个词在多本书里收过只存一份状态 —— 按标注存会让这个词被复习好几遍
- 队列 = 到期的（不受每日上限限制）+ 新词（受 `DEFAULT_DAILY_NEW = 10` 限制）。
  「按天数」和「按单词数」不是两种模式，只是同一个队列的两段
- 侧栏「待复习 N」入口（放在筛选行右侧：它是「去做一件事」，和左边的筛选不是一类）
- 复习面板：一次一个词。
  **释义默认遮住，没显示之前评分按钮是禁用的** ——
  否则释义就在眼前，只是「标记一下」，没有回忆动作；
  **先自己回想、再翻看答案**才是间隔重复起作用的地方。
  释义下面附上**你遇到它的那句原句**。支持空格翻面、1/2/3 评分、Esc 结束

设计取舍：

- **只复习词，不复习笔记**。笔记没有「记得/忘了」这回事
- 复习范围是**整个词表**，跟当前打开哪本书无关
- 面板上的队列在**打开时快照**：不快照的话，每评一次分 store 就变了、
  队列重算，面板上的下标会错位到别的词
- 忘了之后是「5 分钟后再来」而不是「立刻再来」：太短会在一次会话里反复弹同一张卡

已知缺口（新增）：

- **删掉一个词不会清掉它的复习进度**，以后重新收同一个词会拾起旧进度。
  影响很小（“这词你本来就会”），而清理需要反查所有同 key 的标注；暂不做
- **每日新词上限写死 10**，还不能设置。等真实用一段时间再决定要不要放进设置
- **卡片模式的花活还没有**：翻面动画、复习统计、卡片上直跳回原文

## 已修（第二十一轮）

**复习可设置 + 卡片能跳回原文。**

设置（侧栏筛选行右侧那个 ⚙）：

- **每天新词上限**：0~50，默认 10。0 是有意义的（今天只清到期，不引入新词）。
  手改过存档也不会变成 NaN：`normalizeReviewSettings` 会收敛回合法值
- **复习范围**：全部 / 本书 / 手动
  - 本书：读大部头时不想被别的书的词打扰。没打开书时这个选项是禁用的
  - 手动：只过自己手动记的那份名单
- **每日名额是按「当前范围」算的**。不这么做的话，
  「全部」范围下复习过 10 个书的词之后切到「手动」会一个都不给，
  而用户根本不知道为什么。代价是换范围相当于换个名额 —— 个人工具，不在意

卡片：

- 释义下面的**原句现在可以点**：直接去看这句话在原文里的位置
  （复用已有的跳转与「返回」）
- 去看原文会收起面板，但**没评完的词还在** ——
  队列是从到期状态重建的，重新打开接着过就行
- 过完了那一屏会告诉你「接下来 24 小时还有 N 个到期」

顺手修的一个组件问题：
「没有原句」的提示和可点的原句共用了 `.review-context`，
导致「找一张有原句的卡」会点到那个不能点的提示上。已拆成两个 class。

## 三、工程完备性

| 缺口 | 说明 |
|---|---|
| **打包** | 没接 electron-builder，现在只能 `npm run dev` / `npm start` |
| **应用名未定死** | 打包前必须定。Electron 的 userData 目录名优先取 `productName`，一旦和 dev 时不一致，会以为「数据全没了」（其实在旧目录） |
| **代码签名** | 没有证书，Windows 首次安装会弹 SmartScreen 警告 |
| **CSP** | 没配。正文全程用 React 文本节点渲染（无 `dangerouslySetInnerHTML`）且不加载远程内容，风险可控，但打包前应补上 |
| **Lint** | 完全没接。`AGENTS.md` 里写明「补上之前不要假装跑过」 |
| **降级会丢字段** | `deserializeStore` 只保留认识的字段。将来加了新字段后，用旧版本打开再保存，新字段会被静默丢掉 |
| **一个坏掉的 .tmp 会留下来** | 写盘中途被杀进程会留下 `.tmp`，下次启动会直接覆盖它，不会累积 |
| **词库更新要重新打包** | `mini.tsv` 用 `?raw` 编进了主进程 bundle。想独立更新词库得改成 `extraResources` / userData 读取 |
