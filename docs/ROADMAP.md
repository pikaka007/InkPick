# 未完成清单

回答一个问题：**现在这个版本，还缺什么。**

分四档，按「用户实际会撞上的程度」排。已做的功能见 [`MVP.md`](MVP.md)。

---

## 一、会让人想摔鼠标的

| 缺口 | 现状 | 说明 |
|---|---|---|
| **非 UTF-8 文件会乱码** | `readFile(path, 'utf-8')` 写死 | 国内大量 TXT 是 GBK/GB18030，打开就是一片乱码。需要探测编码或让用户选 |
| **同一位置重复收藏会生成两条** | 无去重 | 手滑连点两次就多一条重复记录 |
| **没有自动备份** | 见下方「三」 | `inkpick-store.json` 损坏时退回空库，行为上对但没恢复手段 |

> 原来列在这里的「删了没法撤销 / 笔记不能编辑 / 文档不能删除重命名」已在第十三轮做掉，
> 见 [`MVP.md`](MVP.md) 的已做清单。

## 二、功能上确实没有的

| 缺口 | 说明 |
|---|---|
| **搜索** | 文档内全文搜索 + 结果列表 + 跳转。读长书时很需要 |
| **目录** | TXT 没有章节结构，做不了真目录。目前用可拖的进度条代替（见 [`MVP.md`](MVP.md)）。真做要先有章节标题识别，效果未验证 |
| **高亮颜色** | 现在词条是黄、笔记是蓝，固定配色，不能选 |
| **lemma 归错了没法手动改** | `left → leave` 这类误判只能忍 |
| **键盘快捷键** | 没有。翻页 / 搜索 / 收藏全靠鼠标 |
| **没有自动备份** | `inkpick-store.json` 损坏时 `deserializeStore` 会退回空库 —— 行为上是对的（不崩），但等于标注全丢，且没有恢复手段。另外每改一条标注都会重写整个文件（含全书正文），大书时值得观察 |

## 三、工程完备性

| 缺口 | 说明 |
|---|---|
| **打包** | 没接 electron-builder，现在只能 `npm run dev` / `npm start` |
| **应用名未定死** | 打包前必须定。Electron 的 userData 目录名优先取 `productName`，一旦和 dev 时不一致，会以为「数据全没了」（其实在旧目录） |
| **代码签名** | 没有证书，Windows 首次安装会弹 SmartScreen 警告 |
| **CSP** | 没配。正文全程用 React 文本节点渲染（无 `dangerouslySetInnerHTML`）且不加载远程内容，风险可控，但打包前应补上 |
| **Lint** | 完全没接。`AGENTS.md` 里写明「补上之前不要假装跑过」 |
| **降级会丢字段** | `deserializeStore` 只保留认识的字段。将来加了新字段后，用旧版本打开再保存，新字段会被静默丢掉 |
| **词库更新要重新打包** | `mini.tsv` 用 `?raw` 编进了主进程 bundle。想独立更新词库得改成 `extraResources` / userData 读取 |

## 四、明确不做（及替代方案）

| 不做 | 替代 |
|---|---|
| **EPUB** | 暂缓。真要做得动渲染引擎、CFI 定位、重定位重写三块，见 [`MVP.md`](MVP.md) |
| **复习算法（SRS）** | 导出 Anki CSV，让 Anki 负责 |
| **账号 / 云同步** | 本地 JSON + 可导出。数据不被应用锁死 |
| **PDF** | 固定版式，选中 / 重排 / 定位三件事都难，收益不成比例 |
| **标签** | 目前靠文档 + lemma 分组够用 |
| **多窗口** | 单窗口够用 |
| **完整词典下载** | 实测全量要 1.46GB 内存且词形还原反而失效，见 [`DICTIONARY.md`](DICTIONARY.md) |

---

## 已实测、不用再纠结的事

**不需要虚拟滚动。** 实测（`.dict-src/perf.ts`，真实 Electron 里跑）：

| 书 | 大小 | 打开 | 渲染完 | 段落数 | 滚动响应 | 选中响应 |
|---|---|---|---|---|---|---|
| 普通 | 0.9 MB | 228 ms | 239 ms | 4,420 | 1 ms | 17 ms |
| 中等 | 2.8 MB | 467 ms | 481 ms | 13,260 | 1 ms | 26 ms |
| 大 | 9.5 MB | 1,225 ms | 1,258 ms | 44,199 | 1 ms | 67 ms |

结论：现实中的书（3MB 以内）半秒内开完，全量渲染 React 节点完全撑得住。
等真撞上 10MB+ 的极端文件再说，现在加虚拟滚动是过度设计。
