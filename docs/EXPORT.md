# 导出

导出的意义：**数据不能被这个应用锁死**。没有云同步、没有复习算法都不要紧，
只要词表和笔记能被带走 —— 这是 MVP 的「逃生舱」。

## 范围

侧栏有两个切换：「本文件」/「全部文档」。导出范围**跟侧栏看到的一致**：

| 范围 | 内容 | 文件名 |
|---|---|---|
| 本文件 | 当前文档的标注 | `<文档标题>-词表.csv` / `<文档标题>-笔记.md` |
| 全部文档 | 所有文档的标注，同一个词跨书合并 | `InkPick-全部词表.csv` / `InkPick-全部笔记.md` |

背单词用「全部文档」—— 这样读过的所有书会汇成一本词表。

## Anki CSV（词表）

侧栏「导出 CSV」→ 选择保存位置。

### 列定义

| 列 | 内容 | 例 |
|---|---|---|
| `Word` | 词形还原后的原形 | `strike` |
| `Phonetic` | 音标 | `straik` |
| `Definition` | 全部义项，用 `；` 分隔 | `n. 罢工, 打击；vt. 打, 撞击` |
| `Context` | **历次收藏的原句**，各占一行 | 见下 |
| `Source` | 出处书名，跨书时全部列出 | `示例 · On Reading / second-book` |

### 三个刻意的设计

1. **一个词一行，不是一次收藏一行。**
   否则同一个词的多次收藏会变成多张重复卡片。
   多次收藏的上下文合并进同一个 `Context` 字段，每个一行 —— Anki 卡片背面看起来更清楚。
2. **第一行是表头。**
   Anki 导入时会自动识别并跳过；文件用 Excel / Numbers 打开也自解释。
3. **跨书的上下文按书分组，不交错。**
   同一个词在两本书里都收过时，先列出第一本书的全部上下文，再列第二本
   （书的次序 = 你开始在那本书里标注的先后）。每行上下文旁的 `Source` 能看出自哪本。

### 导入 Anki

1. Anki →「文件」→「导入」
2. 选 CSV，分隔符选**逗号**
3. 字段映射：`Word` → 正面，`Definition` + `Context` → 背面
4. 「允许在字段中使用 HTML」**不用勾** —— 导出的都是纯文本

> 注意：如果释义里有换行，Anki 会把它当成多行字段，这是预期的（RFC4180 的引号包裹）。

## Markdown（词表 + 笔记）

侧栏「导出 MD」。

单文档时的结构：

```md
# <文档标题>

> InkPick 导出 · 2026-09-15 · 3 条词条 / 1 条笔记

## 单词

**strike** /straik/ — n. 罢工, 打击；vt. 打, 撞击

- *(strikes)* While you read, mark what strikes you.

## 笔记

### 这句概括了整本书的动机

> Speed feels like progress.
```

跨文档时结构不同：标题变成 `# InkPick 全部标注`，每条上下文后面用括号标出书名，
笔记按文档分节（`### <文档标题>`）。

- 同一个词的多次收藏归在一条词条下；选中的形态与原形不同时用 `*(strikes)*` 标出来
- 没有词条或没有笔记时，对应小节不输出
- 词典没收录且没手写释义的词，显示 `（未补释义）` 而不是留空

## 释义收敛

ECDICT 的 `translation` 是给词典软件用的，直接拿来当卡片太吵：

```
run 原始   n. 跑, 赛跑, 奔跑, 奔跑的路程, 趋向, 流出, 运转；vi. 跑, 奔跑, 跑步…      （155 字）
run 收敛后 n. 跑, 赛跑, 奔跑…；vi. 跑, 奔跑, 跑步…；vt. 使跑, 参赛, 追究…          （44 字）
```

规则（见 `src/core/senses.ts`）：

1. 去掉领域标记 `[计]` `[法]` `【网络】` 与词尾语域标记 `(archaic)`
2. 最多 3 条义项
3. 每条义项内最多 3 个近义，超出用 `…`

实测效果（整库 23,900 词条）：

| 范围 | 原文 → 摘要 | 比例 |
|---|---|---|
| 全部 | 567,861 → 456,437 字 | 0.80 |
| 长词条（> 80 字） | — | 0.58 |
| `run` | 155 → 44 字 | 0.28 |
| `strike` | 101 → 42 字 | 0.42 |

整体只有 0.80，是因为 23,900 个词条里 **18,254 个只有 1 条义项**，本来就没东西可删；
真正难看的长词条被砍到一半以下。噪声主要来自**义项内部的近义罗列**，而不是义项条数。

**注意：存储里保留的是完整释义，收敛只发生在展示与导出时。**
界面与导出共用同一套规则，所以将来想加「展开完整释义」不需要重新查词库。

## 已知限制

- **不导出阅读位置**：导出的是文本内容，不带可点击跳回原文的位置信息。
- **收敛会丢一部分义项**：被 `…` 截掉的近义只在存储里，导出文件里没有。
  想按自己偏好改规则的话，`summarySenses()` 的两个上限是单一入口。
